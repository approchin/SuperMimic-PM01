# checkpoint 65k：评测协议与边界

本页是已有结果的脱敏说明。数值来自本轮实验总表、三次固定 200 复测的原始结果与摘要，以及已结束的现场记录；本次未重跑这里对应的原生 BF16 评测或现场试验；另有独立协议的新 CPU FP32 视频，见[视频页](videos.md)。首版不包含完整原始评测集、轨迹及日志，因此这些是发布者报告的历史结果，不能仅凭离线推理检查独立重现。

## 完成、回报与误差分别表示什么

“完整片段完成”指计划的参考帧全部执行完，且未触发原生终止。PM01 的原生终止条件是下列任一项：

- 根高度相对参考的绝对误差 `> 0.25 m`。
- 被检查身体的最大参考高度绝对误差 `> 0.30 m`。
- 完整 SO(3) 根旋转误差角的平方 `> 0.8 rad²`，约相当于 `51.2°` 的角误差。
- 原生完成误差出现非有限数值。

比较符号为严格大于。完整根旋转包含朝向差，不能仅解释为倾斜；触发参考跟踪门限也不能单凭标签认定已经跌倒触地。本评测没有额外添加根水平位置或关节角的硬完成门槛，故“完成”不等于“精准跟踪”。

每条动作的全片归一回报为：

`R_clip = 实际获得的奖励总和 / (0.1 × 计划执行步数)`

`0.1` 是固定的一步最大奖励，不取模型自身输出的最大值。提前终止后的计划尾段仍留在分母，不补奖励；面板回报是各动作 `R_clip` 的等权平均。它不同于训练步均奖励、困难采样的折扣回报、想象奖励或带 Critic 尾值的 Actor 目标。

关节误差只统计 23 个策略受控关节，不含外生头部 yaw。每次仿真步后的实际关节角与下一参考帧比较，以度计；先在每条动作的已执行帧及 23 个关节上平均，再对动作等权：

```text
MAE  = mean_clip(mean_executed_frame,joint(abs(error_deg)))
RMSE = sqrt(mean_clip(mean_frame_and_joint(error_deg²)))
帧覆盖率 = 已执行帧数 / 计划帧数
```

终止帧计入，填充帧和终止后的空转帧排除；未执行尾段不以零误差填充。不同完成程度会改变误差覆盖，不能脱离完成率和帧覆盖只比较 MAE。历史任务缺失的误差保留为“未记录”，不以其他任务的数值补齐。

### 随机延迟如何分配

使用独立 `random.Random(13)`，按冻结的动作顺序为每个动作从 `[0,5,10,15,20] ms` 等概率抽取一次，贯穿该动作。相同动作的延迟分配在候选权重间保持一致。执行等待通过保留上一关节目标的物理子步实现，仿真继续推进。

| 固定到该动作的延迟 | 该层动作数 | 完成数 |
| --- | ---: | ---: |
| 0 ms | 29 | 29 |
| 5 ms | 48 | 47 |
| 10 ms | 47 | 45 |
| 15 ms | 38 | 37 |
| 20 ms | 38 | 36 |

各层包含的动作不同，不能把层间分数差异直接归因于延迟大小。该协议是 200 次动作执行；它不同于每条动作在五档延迟各跑一次的 1,000 次全扫。seed 13 同时出现在训练与此处分配记录中，但延迟分配 seed 不代表另一个训练 seed。

### 推扰与站立子面板

正式推扰面板是在 5 条参考上构造的 120 个固定条件，不是 120 条独立动作。采用原生物理共享前缀，在注册事件帧原位恢复状态、历史和延迟队列后，分成推扰与无推对照。扰动是在根部世界水平速度上增加 `Δv = 0.5 或 1.0 m/s`，每档 60 个条件；这是速度增量，不能写成牛顿力脉冲。0/5/10/15/20 ms 延迟按固定条件分配，提前失败保留在计划分母。

其中站立 24 条使用一个固定姿态，条件为 4 个方向 × 3 个事件时刻（1、2.5、4 秒）× 2 个强度。它们是 24 个固定条件，不能当成 24 次独立随机重复。65k 在这 24 条中全程完成 24/24、5 秒内速度收稳确认 24/24；确认时间均值约 `1.800833 s`、中位数 `1.83 s`、P90 `2.334 s`。配对无推对照也为 24/24，在 `0.5 s` 确认。

“收稳确认”自实际施加扰动帧开始计时：世界平面根速度严格低于 `0.10 m/s`、完整角速度范数严格低于 `0.20 rad/s`，连续满足 25 个有效 50 Hz 帧后首次确认。这个时间包含 0.5 秒持续确认窗口，落在 0.02 秒网格；它不保证回到原位置、朝向或关节姿态。上述统计只对成功条件计算，P90 用排序位置 `0.9×(n−1)` 线性插值。

其余 96 个运动条件来自 4 条参考：走、跑、跳 A、跳 B，每条各 24 个条件；其中跑和两条跳为本轮训练已见片段。原协议的绝对静止速度门槛不能解释为运动中的恢复时间，因此这里只报告动作完成和无推对照，不宣称动态参考恢复用时。该仿真推扰面板也不代表机器人已经完成实物抗推测试。

## 数据暴露与选择偏差

固定 200 的 clip 均为 BONES 来源；冻结协议登记了 200 个互异的 source ID，这并不自动证明其与训练录制来源独立。准备记录显示其 clip 与本轮训练池无精确 clip 重合；它仍被反复用于训练监控和模型选择，属于开发/回归集，不能称作一次从未参与选择的最终盲测。历史对通用 3,950 池的来源审计也不能自动扩大为本轮全部来源完全独立的证明。

专项 18 包含已见的 16 条训练参考和 2 条诊断挑战参考。镜像与同一录制的不同阶段具有来源关系，片段不同不能自动推出录制来源独立。65k 的部分独立评测面板未测，不得补成零或推断为通过。单 seed 的不同快照、不同延迟层和重复评测都不是多 seed 结果。

## FP32 导出与目标设备计时

分发的 ONNX 使用 FP32 前向，训练及上面的三次固定 200 复测使用 BF16 MLP。既有目标设备记录用站立、步行共四个状态，对源实现 FP32 和 TensorRT FP32 做了观测、参考、动作和目标角对照，均通过各项预设容差。与记录中的原生 BF16 已发身体指令相比，目标角最大差为 `0.0038965 rad`（约 `0.2233°`）；比较范围很小，并包含后端差异，不能扩展为完整轨迹等价。

既有 Orin / TensorRT 10.3.0 计时在同四个记录输入上轮换，预热 20 次后记录 500 次单线程策略步：

| 项目 | 数值 |
| --- | ---: |
| P50 | 0.946336 ms |
| P99 | 2.705542 ms |
| 最大值 | 2.797312 ms |
| ≥ 20 ms | 0/500 |

采样不按 50 Hz 节拍等待、不含机器人 I/O，仅描述策略推理环节；硬件是否锁频未由这项记录确认。它不包含 ROS 通信、命令刷新、硬件执行和端到端控制延迟。首版不分发该设备生成的 TensorRT 引擎，也没有以 CPU 推理检查重测这些时延。

## 证据可用范围

本页的三次复测指标在各自原始逐动作结果、摘要和汇总中相互核对；历史普通/专项/推扰使用原有任务摘要与派生统计，不跨任务补指标。公开文件保留协议和汇总值，私有机器位置、账号、运行标识、原始现场日志及云备份信息不随首版分发。
